1. *SCANCONFIG* :- Used record since it stores data and shouldnt change after i created it. Path directory refers to the folder which is to be scanned, long minsize is the minimum size of the file, boolean dryrun is like a preview of what would happen(true or false) before deletion happens(like a confirmation), boolean interactivedeleter is like the toggle switch(true or false) whether to delete the dup file or not, jsonreport is the location of the json report and htmlreport is the location of html report(both happens after deletion i.e, json stores the data of the file(s) and html stores the report of the deletion in a html format).

2. *BYTECOMAPARTOR* :- This class compares the files(og and dup) byte by byte from beginning to end therefore this the final verification step for the dupfinder. Used public final class so that it cant be inherited, furthermore if we see the significance of this class then it can be understood like this i.e, using buffers we can read 8192 bytes at time and then 8192 bytes and so on. It's like the system reads everything page by page instead letter by letter so we can conclude that it verifies two files that are truly identical. Inputstream lets us read the bytes sequentially without loading the entire file into the memory so that we can compare the bytes without slacking the performance. This class works after MD5 hashing and MD5 hashing alone cant be trusted as it malole files may have same MD5 hash which may lead to a hash collision, so use of this class is of much greater significance to end the entire verification of the duplicate files.

3. *CLIOPTIONS* :- It reads user's commands, creates the scanconfig(values to the variables created in the scanconfig class) and then the app runs. Options options.. creates all the supported commands. CommandLine cmd.. creates the apache commons cli.
